Version 0.3.0: catalogue document order and script preference
Mangayomi uses pseudom instead of the browser's querySelectorAll:
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/utils/extensions/dom_extensions.dart
https://github.com/hubble459/pseudom/blob/main/lib/src/selector/selector_groups.dart
SelectorGroups accumulates each group's result in insertion order; it does not
merge groups back into document order. The source now selects td once, then
filters classes to keep volume headers interleaved with their chapters.

Wenku8's own Traditionalized / Simplized functions are already loaded by its
normal pages. The source calls them on a detached copy's display text only.
https://www.wenku8.net/GB_BIG5.js
https://www.wenku8.net/novel/3/3496/index.htm
No converter library or mapping from the website is bundled. Login form values
and href/src attributes are excluded from script conversion.

A real-page integration check through the running app's official page helper
verified 120 distinct chapter URLs across nine volumes, two different chapter
bodies, and traditional/simplified output for the same chapter. Only aggregate
statistics and hashes were saved. The source parser ran in a Node VM with a
pseudom group-order adapter. The new source was not installed into the app.

Version 0.3.1: Traditional Chinese search and empty-result pages
Real pages through the running app showed that searching 狗與剪刀 produces
a header-only empty search grid, whereas 狗与剪刀 redirects to book/1284.htm.
The site searches simplified titles; this differs from display conversion.
https://www.wenku8.net/modules/article/search.php

The source now normalizes search phrases locally using OpenCC dictionary data.
Only first output candidates from TSCharacters/TSPhrases are merged into a JS
lookup; longest-match phrase conversion is used. This is not the full OpenCC
engine or its complete normalization/configuration pipeline.

Version 0.3.2: Mangayomi chapter identity compatibility
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/utils/chapter_recognition.dart
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/modules/manga/detail/providers/update_manga_detail_providers.dart
The app combines recognized season/episode/scanlator into a duplicate key and
can discard a different URL with that same key. Chinese volume labels are not
recognized as seasons. For the reported book, all 120 chapters reach the parser
but only 41 survive the upstream duplicate model, with five of ten first-volume
chapters retained. Fullwidth display digits leave identity to the existing URL
fallback, avoid numeric cross-volume read-state inheritance, and keep all 120
URLs. This changes display names only; chapter URLs, body text and order stay
the same. Automatic ASCII episode-number recognition is intentionally unused.
The comparison uses the app's real page helper and a model of these two Dart
functions, not a direct test of the installed reader UI or Android build.

Version 0.3.3: Name-sort compatibility
The user's installed app exposes number, upload-date and name sorting, with no
source-order choice. Chapter display names now start with their global TOC
position, padded to the same width (at least four digits) in fullwidth form.
Name ascending reproduces the TOC's reading order and name descending its
reverse, while fullwidth digits preserve the numeric-dedup workaround. Empty,
invalid and repeated links are excluded before assigning sequence positions.
The real 120-chapter catalogue was checked in both sort directions, as were
synthetic multi-volume, decimal-volume, prologue, illustration and 10001-chapter
cases. URLs and original labels after the generated prefix are preserved.

Version 0.3.4: Reader navigation compatibility (supersedes fullwidth prefix)
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/utils/extensions/manga_extensions.dart
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/modules/manga/reader/mixins/chapter_controller_mixin.dart
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/modules/novel/novel_reader_view.dart
getNextChapter follows getChapterListForReading, which independently sorts by
recognized chapter number, not the chapter-list UI's chosen name sort. Null
number keys preserve database row order, which need not match the TOC after
earlier updates. The leading, padded global sequence now uses ASCII digits;
original volume/title digits remain fullwidth so embedded Ch./Ep./S labels
cannot override it. Distinct, positive sequence numbers keep every chapter
through ingestion dedup and reader dedup while fixing numeric and name order.
The real 120-chapter catalogue was checked against shuffled stored rows:
119 next and 119 previous transitions match the TOC in the reader model.
Active reader filters may still exclude the current chapter and make the app
fall back to unsorted raw rows; initial validation should show all chapters.
This tests models derived from the pinned Dart sources, not installed-reader
button interactions or Android UI. Chapter URLs and original labels remain.

Version 0.3.5: In-app illustration chapter link
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/modules/novel/novel_reader_view.dart
https://github.com/kodjodevf/mangayomi/blob/v0.9.9/lib/services/get_html_content.dart
The native reader's img/source TagExtension returns an empty widget whenever
epubBook is null; online source chapters use that path. Its onLinkTap handler
opens /mangawebview for normal anchors. Chapters containing retained images now
include a visible, escaped link to their original Wenku8 chapter URL and an
image count. Text-only chapters are unchanged. Cleaning downloaded HTML keeps
only trusted Wenku8 chapter anchors and removes all other anchor attributes.
Images remain in the returned HTML, but this does not enable inline images or
offline image viewing. Existing downloaded chapter HTML must be downloaded
again to gain the link. Seven focused regression tests cover image-only and
mixed chapters, text-only/empty content, repeated cleaning, URL restrictions,
escaping and the source language setting. Native UI clicks and Android WebView
rendering still need device confirmation.

Version 0.3.6: Remove the illustration fallback banner
The user confirmed that the custom Windows reader renders illustrations inline.
Source output now contains the chapter heading and original sanitized body,
without the generated WebView illustration action or image-count paragraph.
All sanitized images and their order are preserved, including image-only
chapters and images inside stripped external anchors. The seven Wenku8
regressions now assert this behavior in both source language settings.
Existing downloaded HTML must be downloaded again to remove its old banner.
The upstream unmodified 0.9.9 reader still hides online images.
